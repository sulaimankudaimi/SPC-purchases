# DECISIONS.md — القرارات (القسمان 2 و7 من الخطة)

## القسم 2 من الخطة: القرارات المعتمدة (D1–D12)

| رقم | القرار |
|---|---|
| D1 | المكدس: Electron + electron-vite + React + TypeScript + Tailwind CSS (دعم RTL) + Recharts للرسوم + Zod للتحقق + Vitest للاختبارات الوحدية + Playwright (وضع Electron) للاختبارات الشاملة. التغليف بـ electron-builder (مثبّت NSIS). |
| D2 | توليد PDF: قالب HTML/CSS بحجم A4 يُحوَّل بـ webContents.printToPDF من نافذة خفية. هذا يضمن تشكيل الخط العربي الصحيح ويتحكم بالتخطيط حرفياً. (مكتبات PDF المباشرة مرفوضة لضعف دعم العربية.) |
| D3 | صيغة الرمز: spc D-M-YY (n) كما في السجل الفعلي، حيث n تسلسل داخل اليوم يبدأ من 1 دائماً؛ يُولَّد داخل قاعدة البيانات لمنع التكرار. (ملاحظة: الرمز SPC/26/0 في الاستمارة قيمة نموذجية، والشرطة المائلة غير صالحة في أسماء الملفات.) |
| D4 | الحالات: pending قيد الانتظار، executed تم التنفيذ، on_hold تريث، rejected مرفوض، cancelled ملغى؛ على مستوى الطلب. |
| D5 | المصادقة: Supabase Auth بالبريد وكلمة المرور، التسجيل العام معطّل، مستخدم/مستخدمون يُنشَؤون يدوياً. كل الجداول تحت RLS للمستخدمين الموثَّقين فقط. |
| D6 | العمل بلا إنترنت: الطلب الجديد يُحفظ محلياً في «صندوق صادر» ويُرفع تلقائياً عند عودة الاتصال؛ القراءة الأخيرة تُخزَّن مؤقتاً للعرض. |
| D7 | الخط: Sakkal Majalla (خط ويندوز النظامي) أساسي، مع بديل مفتوح الترخيص Amiri مضمَّن في الحزمة. لا يُضمَّن ملف Majalla نفسه لأسباب الترخيص. |
| D8 | القالب: مطابق للاستمارة في الهيكل والترتيب والنصوص والحدود، مع تصحيح nots→Notes وتثبيت عرض Quantity. |
| D9 | الأرقام والتواريخ: أرقام لاتينية (0-9) كما في الملفين، وتحويل الأرقام الهندية (٠-٩) عند الإدخال؛ التاريخ DD/MM/YYYY. |
| D10 | أرشيف PDF: يُحفظ نسخة محلية في مجلد قابل للضبط (الافتراضي Documents\ارشيف spc\الرمز>.pdf) ونسخة في Supabase Storage (حاوية خاصة)، ويُسجَّل المساران. |
| D11 | خانة اسم «الطالب» في جدول التواقيع: تُعبَّأ تلقائياً باسم مقدم الطلب (الاستمارة الأصلية تتركها فارغة)؛ يمكن تعطيل ذلك من الإعدادات. |
| D12 | التوقيع والتغليف: التطبيق غير موقَّع رقمياً في الإصدار 1 (تنبيه SmartScreen عند أول تشغيل مقبول)، ولا تحديث تلقائي؛ التحديث بإعادة التنصيب مع بقاء البيانات في السحابة. |

## قرارات مفتوحة بقيم افتراضية (أ)–(د) من الخطة

قرارات مفتوحة بقيم افتراضية (تُعتمد القيمة ما لم تُغيَّر):
- **(أ)** هل المستخدمون أكثر من شخص؟ الافتراضي: مستخدم واحد مع إمكانية إضافة آخرين.
- **(ب)** هل يلزم تصدير السجل إلى Excel بنفس تخطيط الملف الحالي؟ الافتراضي: نعم.
- **(ج)** أيقونة التطبيق: الافتراضي أيقونة بسيطة مولَّدة، وتُستبدل بملف .ico يقدمه المستخدم.
- **(د)** هل تُحذف الطلبات؟ الافتراضي: حذف ناعم (deleted_at) فقط.
